## 어떻게 선정했는가

1. 참고답변 전체 직접 일치 후보도 질문의 요구 사실과 절 내용을 검토했다. 최종 154개 매핑은 참고답변 전체를 실제 원문 인용으로 기록했다. 정책명 질문은 title 청크를 선택해 다른 청크의 반복 접두어를 정답으로 삼지 않았다.
2. 자동 APPROVE가 없던 53개 Gold 연결은 문장·조건·금액·기간·예외를 청크 본문과 직접 비교해 55개 매핑을 선정했다. 공백/기호 제거 점수는 최종 승인 근거로 쓰지 않았으며, 실제 청크 ID를 명시한 결정 목록과 항목별 이유를 보존했다.
3. `oy_eval200_new_0053`은 자동 APPROVE를 뒤집었다. 질문은 신청방법인데 참고답변은 자격만 담고 있기 때문이다. 원문의 업로드 안내와 신청URL을 담은 두 실제 청크를 선정했다. 참고답변은 그대로 보존하고 아래 품질 유의 항목으로 남겼다.
4. 여러 청크/Gold가 나눠 지지하는 답변은 합집합의 근거 범위로 판단했다. 각 청크가 참고답변의 모든 문장을 단독으로 입증한다고 주장하지 않는다. 최종 relevance=1은 질문의 답변에 필요한 직접 사실을 담은 선정 청크에만 부여했다.

전체 후보 2,548개 중 211개를 선정했고 나머지 2,337개는 최종 정답 집합에서 제외했다. 제외 표시는 부분적 관련성이 전혀 없다는 뜻이 아니라, 이번 정답 집합의 직접 근거로 채택하지 않았다는 뜻이다. 수작업으로 작성한 정답 집합과 마찬가지로 가능한 모든 의미상 관련 청크를 완벽하게 열거했다는 보장은 없다.

## 결과물 안내

- `query_review_summary.csv`: 200개 질문별 선정 chunk_id와 판단 이유.
- `quick_review.csv`: 위 9문항/15개 매핑만 추린 빠른 확인용 자료.
- `approved_evidence_audit.jsonl`: 211개 매핑의 질문·답변·본문·원문 직접 인용·실제 위치·이유·검수자.
- `delegated_review.csv`: 기존 후보 컬럼을 유지하고 위임 검수 결과를 입력한 전체 2,548행.
- `exception_decision_plan.json`: 53개 보류 Gold 연결의 명시적 선정 ID 및 판단 이유.
- `final_validation_report.json`: 독립적인 원문·위치·연결·범위 검증 결과.
- `runner_preflight_report.json`: Runner의 Index 이전 실제 단계 통과 결과.
- `delegation_receipt.json`: 사람 직접 검수가 아닌 사용자 위임 검수임을 명시한 감사 기록.
- 상위 폴더 `qrels_chunk.human_approval.json`: 기존 생성기 파일명은 유지하되 `approval_mode=user_delegated_agent_review`, `not_human_manual_review=true`로 실제 검수 방식을 명시했다.
- 상위 폴더 `qrels_chunk.meta.json`: Runner 계약에 따른 `reviewed` 상태, 청크 버전/해시 및 원본 Document qrels 해시.

기존 `human_review_v1` 검수자료 및 Runner의 원래 candidates/review_required 파일은 그대로 보존했다. 기존 review_required 파일의 207행은 이전 자동 매핑 결과이며 최종 검수 상태가 아니다. 현재 상태는 final qrels와 meta 및 Runner preflight가 나타낸다.

## 이제 실행할 명령

가상환경을 유지한 프로젝트 루트에서 실행한다.

```powershell
python -m src.experiments.runner --config configs/experiments/exp_full_kure_200_v1.yaml
```

청크/정답 사전 검증은 통과했다. 이후 임베딩 모델 로딩·Index 생성·검색 평가 단계는 아직 실행하지 않았으므로 그 단계의 성공이나 지표를 미리 보장하지 않는다.
