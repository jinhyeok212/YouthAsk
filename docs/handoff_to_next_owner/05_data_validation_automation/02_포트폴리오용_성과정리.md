# 포트폴리오용 성과 정리

## 프로젝트 내 역할

온통청년 정책 데이터를 기반으로 한 RAG 실험 자동화 프로젝트에서 데이터셋/전처리 담당을 맡았다.

주요 역할은 공개 API 기반 정책 데이터를 RAG 실험에 사용할 수 있는 표준 문서 스키마로 변환하고, 후속 청킹·임베딩·검색 평가 단계가 안정적으로 실행될 수 있도록 데이터 검증 자동화를 구현하는 것이었다.

## 문제 정의

초기 데이터는 온통청년 API 원본 필드 구조 그대로 수집되어 있었기 때문에, 바로 RAG 파이프라인에 사용할 수 없었다.

문제는 크게 네 가지였다.

```text
1. 정책별 필드 구조가 RAG 문서 스키마로 통일되어 있지 않음
2. 후속 청킹 담당자가 어떤 필드를 기준으로 쪼개야 하는지 불명확함
3. document_id 중복, 빈 제목, 빈 본문 등 데이터 품질 문제가 실행 전에 차단되지 않음
4. 자동화 Runner에서 데이터 검증 단계를 함수로 호출할 수 있는 구조가 필요함
```

따라서 단순히 데이터를 저장하는 것이 아니라, RAG 실험 자동화의 첫 번째 검증 단계를 담당하는 데이터셋 모듈이 필요했다.

## 수행 작업

온통청년 전체 정책 2,728건을 `documents.jsonl` 형식으로 변환했다.

문서 단위는 다음 기준으로 설계했다.

```text
one policy = one document
```

각 정책 문서는 다음 핵심 필드를 갖도록 정리했다.

```text
document_id
title
source
url
content
retrieval_text
metadata
raw_record
```

특히 후속 검색과 청킹에서는 `retrieval_text`를 공식 기준 필드로 사용하도록 명확히 분리했다.

## 자동화 구현

데이터 검증 모듈을 Runner에서 바로 호출할 수 있도록 구현했다.

```python
from src.data.validate_documents import validate_documents

dataset_info = validate_documents(config)
```

이 함수는 Runner의 첫 데이터 검증 단계에서 호출되며, 검증 성공 시 다음 정보를 반환한다.

```json
{
  "document_path": "data/processed/ontong_youth_full_v1/documents.jsonl",
  "manifest_path": "data/processed/ontong_youth_full_v1/dataset_manifest.json",
  "document_count": 2728,
  "sha256": "8688055b4553c79e9390e31831b5fefbef00925f24fb20af983a7ca552914a48"
}
```

이 반환값은 후속 청킹 단계에서 `dataset_info`로 전달된다.

## 검증 항목

데이터 검증 자동화에서는 다음을 확인한다.

```text
documents.jsonl 존재 여부
dataset_manifest.json 존재 여부
JSONL 파싱 가능 여부
각 줄이 JSON object인지 여부
필수 필드 누락 여부
빈 document_id
빈 title
빈 retrieval_text
빈 category
중복 document_id
manifest document_count와 실제 문서 수 일치 여부
manifest sha256과 실제 파일 SHA256 일치 여부
dataset_version 일치 여부
preprocessing_version 일치 여부
```

검증 실패 시 조용히 넘어가지 않고 예외를 발생시켜, 잘못된 데이터가 후속 청킹 단계로 넘어가지 않도록 했다.

## 포트폴리오용 한 줄 요약

온통청년 정책 API 기반 2,728건의 정책 데이터를 RAG 실험용 `documents.jsonl` 스키마로 표준화하고, SHA256 기반 manifest 무결성 검증 및 Runner 연동형 `validate_documents(config)` 데이터 검증 자동화를 구현했다.

## 이력서용 bullet 예시

- 온통청년 정책 데이터 2,728건을 RAG 검색 실험용 `documents.jsonl` 표준 스키마로 변환하고, 후속 청킹/임베딩 파이프라인 입력 데이터로 정리
- `document_id` 중복, 필수 필드 누락, 빈 본문, JSONL 파싱 오류, manifest count/hash 불일치 등을 자동 검증하는 `validate_documents(config)` 모듈 구현
- SHA256 기반 `dataset_manifest.json`을 생성하여 데이터 버전과 파일 무결성을 추적할 수 있도록 설계
- Experiment Runner에서 호출 가능한 데이터 검증 계약을 구현하여, 잘못된 데이터가 후속 청킹 단계로 넘어가지 않도록 fail-fast 구조 적용
- fixture 기반 테스트를 작성해 정상 데이터, 깨진 JSONL, 중복 ID, 빈 필드, version/hash 불일치 등 주요 실패 케이스 검증

## 자기소개서용 문장 예시

RAG 프로젝트에서 데이터셋/전처리 담당으로 참여하여 온통청년 정책 API 데이터를 검색 실험용 표준 문서 스키마로 변환했습니다. 단순히 데이터를 저장하는 데 그치지 않고, `dataset_manifest.json`에 문서 수와 SHA256을 기록하고 Runner에서 `validate_documents(config)` 형태로 자동 검증할 수 있도록 구현했습니다. 이를 통해 후속 청킹, 임베딩, 검색 평가 단계가 신뢰할 수 있는 입력 데이터를 기반으로 실행되도록 만들었습니다.
