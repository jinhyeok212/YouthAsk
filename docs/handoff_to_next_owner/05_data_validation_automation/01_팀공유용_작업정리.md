# 2번 데이터셋/전처리 담당 작업 정리

## 1. 담당 역할

이번 파트의 역할은 온통청년 정책 데이터를 RAG 실험 자동화 파이프라인에서 사용할 수 있는 표준 입력 데이터로 만드는 것이었다.

전체 Runner 흐름 안에서 2번 담당 모듈은 다음 위치에 들어간다.

```text
Runner
→ config 검증
→ validate_documents(config)        # 2번 데이터 검증
→ contracts.validate_stage_result()
→ build_chunks(config, dataset_info) # 3번 청킹 담당
```

즉, 2번 파트는 후속 청킹, 임베딩, 검색 평가가 시작되기 전에 데이터가 올바른지 확인하는 관문 역할을 한다.

## 2. 작업 배경

기존 MVP 단계에서는 온통청년 정책 400개와 평가 질문 47개를 대상으로 RAG 실험을 준비했다.

이후 팀의 목표가 전체 실험 자동화로 확장되면서, 온통청년 전체 정책 데이터를 공통 스키마로 변환하고 Runner에서 자동 검증할 수 있는 구조가 필요해졌다.

이번 작업에서는 전체 온통청년 정책 2,728건을 대상으로 다음을 수행했다.

```text
전체 정책 데이터 로딩
→ RAG용 documents.jsonl 생성
→ dataset_manifest.json 생성
→ data_quality_report.csv 생성
→ SHA256 기록
→ validate_documents(config) 자동 검증 함수 구현
→ fixture 기반 테스트 작성
```

## 5. documents.jsonl 구조

문서 단위는 다음과 같다.

```text
one policy = one document
```

각 문서는 다음 필드를 가진다.

```json
{
  "document_id": "ontong_youth_정책번호",
  "title": "정책명",
  "source": "ontong_youth",
  "url": "대표 URL",
  "content": "정책 주요 필드를 결합한 전체 본문",
  "retrieval_text": "검색과 chunking에 사용할 본문",
  "metadata": {
    "dataset_version": "ontong_youth_full_v1",
    "primary_category": "대분류",
    "primary_mclsf": "중분류",
    "application_period": "신청 기간",
    "document_quality_score": 000,
    "normalization_status": "OK"
  },
  "raw_record": {
    "plcyNo": "...",
    "plcyNm": "...",
    "plcySprtCn": "...",
    "plcyAplyMthdCn": "..."
  }
}
```

후속 청킹 담당자는 `content`가 아니라 `retrieval_text`를 기준으로 사용하면 된다.

## 7. 자동화한 부분

Runner에서 호출 가능한 데이터 검증 함수를 구현했다.

```python

dataset_info = validate_documents(config)
```

예상 config:

```python
config = {
    "dataset": {
        "version": "ontong_youth_full_v1",
        "preprocessing_version": "prep_v1",
        "document_path": "data/processed/ontong_youth_full_v1/documents.jsonl",
        "manifest_path": "data/processed/ontong_youth_full_v1/dataset_manifest.json",
        "quality_report_path": "data/processed/ontong_youth_full_v1/data_quality_report.csv"
    }
}
```

반환값:

```json
{
  "document_path": "data/processed/ontong_youth_full_v1/documents.jsonl",
  "manifest_path": "data/processed/ontong_youth_full_v1/dataset_manifest.json",
  "quality_report_path": "data/processed/ontong_youth_full_v1/data_quality_report.csv",
  "document_count": 2728,
  "sha256": "8688055b4553c79e9390e31831b5fefbef00925f24fb20af983a7ca552914a48",
```

## 8. 검증 항목

`validate_documents(config)`는 다음을 검증한다.

```text
documents.jsonl 존재 여부
dataset_manifest.json 존재 여부
JSONL 파싱 가능 여부
각 줄이 JSON object인지 여부
필수 필드 존재 여부
빈 document_id
빈 title
빈 retrieval_text
빈 category
중복 document_id
manifest document_count와 실제 문서 수 일치 여부
manifest sha256과 실제 documents.jsonl SHA256 일치 여부
config dataset.version과 manifest dataset_version 일치 여부
config preprocessing_version과 manifest preprocessing_version 일치 여부
```

원본 문서에는 top-level `category`가 없고 `metadata.primary_category`가 있으므로, 이 값을 category로 인정하도록 처리했다.
